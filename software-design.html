Software Design and Engineering

CS 360 Weight Tracker Android Application

Download Original and Enhanced Code Download Narrative

Artifact and Origin

The artifact I chose is my Weight Tracker Android app, which I created for a previous mobile development course, most likely CS 360. The original app was written in Kotlin and let a user create an account, sign in, record and delete weights, set a goal weight, and configure an SMS reminder. I selected the existing project files as the starting point for this enhancement. I do not have the exact date I originally created the app.

Why I Chose It and What I Changed

I chose this app because it already has several connected features, so its design decisions affect a real user experience. In the original version, the screens called the database helper directly. The database also stored passwords as plain text, and weight entries and the goal were shared across accounts.

For this milestone, I added a service layer and a repository interface so the screens handle display and interaction while the service handles validation and application rules. Database work now runs away from the main screen thread. I added input checks, a progress summary on the dashboard, and a logout action.

New accounts use salted password hashes, and an existing plain text password is upgraded after a successful sign in. I changed database access so entries and goals belong to an account, and I wrote an upgrade path meant to preserve existing records. The downloadable ZIP file contains both the original and enhanced source code.

Course Outcomes

This work makes the most progress toward the outcome about using appropriate computing techniques and tools to deliver a useful solution. I used Kotlin, Android activities, a service and repository structure, and SQLite to make the app easier to extend.

It also supports the security outcome because account data is separated, passwords are handled more carefully, and input is checked before saving. I practiced evaluating tradeoffs when deciding how to migrate older shared records. The upgrade assigns them to the oldest existing account, or to the first newly created account if no account existed.

My narrative and code review support the communication outcome. I still plan to show more algorithm and data structure work in the CS 330 graphics project and deeper database work in a later Weight Tracker enhancement.

Reflection and Remaining Work

The hardest part was changing an app that already had saved data. Replacing the database tables without a migration would erase a user's history, so I had to think through what should happen when older entries had no account owner.

I learned that moving code into separate classes is only useful when the responsibilities are clear and the screens still behave correctly. I added unit tests for validation and password handling and Android tests for the database upgrade and account separation.

I checked the XML files, but I could not run the Gradle or Android test suite in the original development environment because the required Gradle distribution could not be downloaded. Before the final ePortfolio submission, I planned to build and run the app in Android Studio, run the tests on an emulator, and use instructor feedback to address any issues. The SMS feature still uses the emulator number from the original course project, so that feature would need additional review before being used outside a class demonstration.
